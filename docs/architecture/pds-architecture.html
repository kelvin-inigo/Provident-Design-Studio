Section 01

PDS at a glance

PDS is Provident's in-house brand production suite. Designers, performance marketing, the content team and social media use it to make on-brand ads and posts and pass them between teams for review. It's a static web app with no build step: plain HTML and JavaScript documents, two small Python serverless functions, Google Drive as the system of record, and optional helper services on the designers' Macs.

3studios: CAS and OPS (live), CASV (local prototype)
2serverless functions: /api/share, /api/gauth (Python, Vercel)
8studio tools exposed over MCP, to Claude (stdio) and the Grok bot (https)
0build steps. Every file is served as written; there's no bundler and no npm
~62klines across the two studio documents and their shared scripts
8roles, from admin to ctar, with an admin-editable capability map

Design principles worth knowing before you touch anything

  • The canvas and the chrome are separate systems. Artwork reads brand palette literals (CampaignStudio.PAL, OrganicStudio.ART). The UI reads --ps-* CSS tokens. Mixing them once leaked UI blue into finished posts.
  • Preview and export share one geometry. Every component and template has a single layout function, read by both the on-screen preview and the exporter.
  • Drive is the record of truth for ad sets, projects, posts and exports. Access to the data is Drive sharing. The in-app role gate only shapes the UI.
  • Local helpers are capabilities, never requirements. When rembg, the Photoshop helper or CASV isn't running, the feature that uses it disappears and nothing else breaks.
  • Agents drive the real app. The MCP server opens the actual studio documents in headless Chrome, so no artwork logic is duplicated for AI use.

Three ways in

People, in a browser

Open the live site on Vercel (or a local copy). Home is the starting point; it opens CAS or OPS on the right project and links out to CASV on localhost:8794.

Claude, on a Mac

Claude Desktop and Cowork reach CAS and OPS through the provident-studio MCP server (stdio). Skills such as /hub-design-queue build on those tools.

The Grok bot, remotely

The same tools (eight for CAS and OPS, four video tools that build a CASV project and hand it to the designer) are served over https by remote.py on the office Mac, behind a tunnel. Each person gets their own token.

Section 04

In-browser runtime and shared code

Each studio is one self-contained Design Cursor document (.dc.html): markup with {{ }} interpolation, a <helmet> stylesheet, and a text/x-dc script holding the engine class and the shell Component. The two studios share code through plain script files that load before the DC block.

runtime.js

  • Workspaces. Every tab gets ?ws=<id> (from the URL, else sessionStorage, else a new id). Per-workspace localStorage keys are prefixed ws:<id>:. This stopped parallel Cowork sessions from overwriting each other. ?ws=shared is the opt-out. Workspaces older than 30 days are pruned.
  • Storage stand-in. image-slot.js gates editing on window.omelette.writeFile, which only Design Cursor provides. The runtime backs it with IndexedDB and serves .image-slots.state.json from there. A new workspace starts with an empty photo store.
  • One image encoder, providentEncodeFile: one export-grade copy per image, long side capped at 3840 px. WebP, JPEG on older Safari, PNG when the image needs alpha.
  • Safari fallbacks for letter-spacing, WebP, roundRect and backdrop-filter.

studio-base.js

  • The DC logic surface (state, setState), text metrics (meas, wrapRuns), zip, buildPdf, saveAs, session load and save, the project folder (File System Access API) and recents.
  • window.providentDrive: Google sign-in, token renewal and Drive fetch with a retry on 401 (section 10).
  • Content Hub reads (hubFetch, hubLoad, hubOpenItem), home navigation (goHome) and the inbox queues.

Session files and hand-over

  • CAS saves .adstudio.json; OPS saves .smpstudio.json. Opening one studio's file in the other navigates to the right studio.
  • Photo slot ids are prefixed per studio (adstudio-*, smp-*), so the shared photo store never collides.
  • Recents hold saved projects only (10 per studio), with their photos kept apart per project.
Section 05

CAS: Campaign Ads Studio

CAS makes paid ads for real-estate campaigns: branded or Unbranded Meta statics, Eventbrite banners, an animated video-background version, and the review hand-off between designer, content team and performance marketing. Every project belongs to a campaign "ad set" on Drive.

Flow, from brief to export

  • Brief sheet (PlanView): the campaign name, product, deadline and Drive folder, the brief and attachments, audiences, and broad or audience-based reach. Then Start designing or File as ticket.
  • A ticket is an ad set with no project yet. dsMakeSet writes <name>_Adset.json and Brief/ into the campaign's Drive folder. Pick up creates the project.
  • Ad set tab: overview, stage action, steps, audiences, brief, activity, team links, the Deliverables checklist (Static · Animated · MVP video), the Copy card and the Video section.
  • Design view: a layers rail over a component palette, one canvas plate per variant, the component inspector and Layout rail, and the all-variants dock (QR, typeface pair, co-brand logo, Add variant).
  • Generate (Generative fill, 2026-11-20): a button in the Photo row after Reframe opens genfill.js's editor on the variant's main photo. Pick a size (1:1, 3:4, 9:16, 1.91:1, 2:1 from PXT); the photo snaps edge to edge on the fitting axis (Photo size 50–100% shrinks it), a crosshair sets the focus kept in frame, "Show copy margins" draws the size's pad, and 1–3 variations come back from the chosen engine: Nano Banana 2.1 through Higgsfield (the default, priced on the button from the helper's /quote, with an optional description) or Firefly Generative Expand. For Nano Banana CAS composes the whole frame at the model's nearest shape (nanoPlan; 1.91:1 and 2:1 go at 16:9), bands roughed in, plus a mask of the bands, and crops the result back. The original is pasted back over the middle. Use on a size writes adstudio-bg-<vi>-<size> and sets bgSep[size]; 1:1 writes the main photo. No paint path changed. Needs the helper on :7315 on that computer; without it Generate is disabled with the start command.
  • Share › Export: JPEG 2×, PNG 2×, SVG or PDF, then a counted button such as "Export 6 JPEGs". Animated export appears when a variant has a video background. In the Ad sets window and the placement preview an animated design plays live (anLive): each build and frame runs under the design's own face (CampaignStudio.anFace, globals put back after) once that face has loaded (anFaceReady), and the live canvas is always held inside its tile.

Component system

  • Component types: eyebrow, hero, hook, body, list, tags, spec, steps, price, cta, divider, spacer, graphic, and cust. Custom components come from the /cas-component skill.
  • Type ladder: a minor third ×1.2 from a 24 px floor, TYPE = [24, 28, 35, 41, 50, 59, 71, 85, 103, 123, 148, 177, 212].
  • S / M / L / XL steps the ladder by −1 to +2. They're applied only where layout is computed (tkMod), so the preview and the export can't drift apart.
  • modLayout → buildOps → renderOpsToCanvas / renderOpsToSvg. Changes are proven with an op census against the previous build.
  • QR code | ADM & CN: the QR block can print the ADM permit (typed, digits) over CN 6323926 (fixed) in the code's corner instead of the code. qrBox is the one source of that corner's box; admEls lays the two lines out for both renderers and the preview. State qr.mode / qr.adm.
  • The ad set's QR code (2026-11-20): Ad set settings › QR code takes one upload (qrPng: a PNG of at most 600 px on white), saved on the ad set as rs.qr = { u, name, id, by, at } through the edit op (null clears it). Every CAS design in the ad set fills its own adstudio-qr from it when opened (rsQrApply, after a poll has settled the design's pictures; once per id, remembered in the design as qr.rsq), so it is saved, exported and drawn with the design. Status and its downloads (RV.photos) draw the ad set's QR for a design that has not taken it yet. A QR replaced by hand in one design stays until the ad set's QR changes.
  • AED draws as the Dirham sign (U+20C3). The copy keeps "AED"; CampaignStudio.aed() swaps it in meas(), both renderers and the editor's element views, and 'Dirham-Sans' (unicode-range: U+20C3) leads every canvas stack. The face is the package's outline rebuilt at the figures' cap height (make-cap.py); the SVG export embeds it (1.5 KB) when it is used.
  • Carousel mode: up to 10 pages. Each page is a variant with its own component list.
  • Unbranded look: tone, a five-role palette, Google Fonts, radius, blur and tracking. There's no wordmark or QR. It's set per project and can be mixed per audience.

Copy and Arabic

Pasted copy is parsed line by line (brPlain; an audience line reads Family:) and inserted in reading order. The content team edits in the Edit text layer.

Write the Arabic calls /api/share?op=arcopy, where Claude (claude-opus-5-5, team rules in AR_RULES, structured output) writes the translation. If that fails, Chrome's built-in translator and the Google Translate endpoint are the fallbacks. The whole ad mirrors for right-to-left.

Video background

Background › Photo | Video on a variant. A muted <video> plays inside the photo slot's frame, using the slot's crop.

The panel shows the clip card (name, length, Drive state) and three ways to add or replace it. Generate from the photo uses Higgsfield (camera move, 5 or 10 s, Kling, Cinema or Seedance, Draft or Full): it shows the price first, and a second press spends the credits. CAS never calls Higgsfield itself. It posts a 1080×1920 start frame to CASV's local server (/api/animate/job → cost → run) and polls every 4 s. A photo wider than 9:16 is not cropped by default (Extend to 9:16, as in CASV): the frame is the whole photo between grey bands, sent with extend and the band, and CASV's server has Nano Banana 2.1 paint the bands before the clip is made (priced in the same total). Upload a clip takes an MP4. Edit in CASV is a round trip: CASV opens a fresh video with the photo, its Send back to CAS records the 9:16, and CAS picks it up from /api/outbox/file?part=bg.

The clip is saved to Drive as the project's Assets/video-background-variant-<x>.mp4 (the variant keeps bgClip), with a copy in IndexedDB provident-cas-clips. A clip added before this goes up to Drive by itself when the project is reopened. Animated designs get an Animated pill on Status. They autoplay in the placement preview and in the PM's and content team's views. The PM's Download records the animated MP4s into the zip beside the stills.

Sizes and export

  • Feed 1080 × 1440 (3:4, 80 / 90 margins). Story 1080 × 1920 (9:16, 200 top margin), included only while the Story switch is on.
  • Exports are flat: <name>_3x4.<ext> and <name>_9x16.<ext> in PNG, JPG or PDF. The PDF contains the feed pages only.
  • Name prefixes come from FILETPL: Carousel_<head>, Weekly Listing_<Week>, Top Agents_<date>_<team>, Reel_Thumbnail_<date> and so on.
  • A property page can't be exported until it has both its QR and a listing number.
  • Fonts, textures and award layers are bundled as data URIs, so OPS renders offline.

Guided run and All controls

  • The guided run is a page-by-page view of the same workspace, not a separate flow. It asks only for per-post content (FIELDS); LOCKED and FIXEDTEXT name what the template owns.
  • All controls: pages as layers with real thumbnails, the size row, and the post-look inspector (Story, scrim, wash, photo strength, logo, panel colour).
  • Both are rendered from one markup. A change lands in both, and both directions are checked.

Posts on Drive (post-flow.js)

A post is a folder in the shared Drive posts root (FILES_ROOT in post-flow.js), filed by type: Weekly Listings/<Month Year>, Top Agents/<Team>, Reel Thumbnail, Just Listed & Sold, Google Reviews, Awards or Carousel. The folder holds:

  • <name>_Post.json: the record (ticket, items, steps, log, role tokens)
  • <name>.smpstudio.json: the project
  • Assets/, Brief/ and the exports

The project syncs to Drive about every 2.5 seconds. A "Just me" post has no record and doesn't appear on Status. A new post stays hidden from Status until its first save.

The content team never gets the OPS editor. They review words only, in a frame opened at OPS?cc=1#share=<sid>, with Approve copy or Back to design. The one exception is Content Hub posts, whose copy is already approved in the hub.
Section 07

CASV: Video Studio prototype

CASV is a simple multi-track video editor for the "MVP video" deliverable of an ad set. It runs on the designer's own Mac, never signs in, and never touches Drive itself; the website does the Drive work when the video comes back to CAS.

What it is

  • Files: Provident Video Studio.html, video-studio.js (plain JS, not DC), video-dev-logos.js, video-icons.js, tools/video-dev/serve.py.
  • Sizes: Reel 9:16 (1080 × 1920) and Square 1:1 (1080 × 1080).
  • Tracks: Text, Graphics, Video (magnetic), Music, Sound. Captions timed to a voiceover; cut, fade, wipe, slats and dip transitions; callouts; an end card; markers.
  • Text follows the OPS reel-thumbnail style. The co-brand logo is CAS's lockup.
  • Branch video-studio, local only and never pushed. The prototype has a single project and no Recents.

Server routes (serve.py, port 8794)

/api/animate/*Animate queue (_animate/): job, jobs, placed, cancel, cost, run, file. Also used by CAS's Generate from this photo. A describe job (Have Claude write it from the photo) is written at once: serve.py runs Claude Code headless (claude -p, Sonnet, Read only) on the start frame with the photo-to-video-prompt skill
/api/music/*Generate music (cost, make)
/api/voice/*Voiceover: macOS say or Higgsfield text-to-speech
/api/outbox/*file, meta, list, notes, back. Hand-off to CAS (_outbox/)
/api/inbox/*list, file, done. Videos sent back from CAS (_inbox/). photo: CAS's Edit in CASV start frame

CORS allows the live site, localhost and CASV_ORIGINS, and answers Chrome's private-network preflight.

Higgsfield: turning photos into motion

  • A photo clip's inspector offers Animate with Higgsfield: 10 camera moves, 5, 8 or 10 seconds, Draft 720p or Full 1080p, and a choice of model (Seedance 2.5, Kling 3.0 or Cinema Studio).
  • Send to the animate queue: the /animate-photos skill quotes the cost and waits for a yes, then runs Higgsfield through its MCP and marks the job done. The page polls every 4 seconds and swaps the clip in.
  • Have Claude write it from the photo (under Length): free, about a minute. serve.py finds Claude Code (claude on PATH, else the desktop app's own copy) and needs it signed in once on the Mac: serve.py --claude-login. Not signed in, the clip says so with that command; /animate-photos still answers the job the old way.
  • Extend to 9:16 (or 1:1), on by default for a photo wider than the video: the start frame is the whole photo centred between grey bands; serve.py has Nano Banana 2.1 (nano_banana_2_1, 2k, about 2 credits, priced into the same confirm) paint the bands, pastes the original photo back over the middle (Pillow) and animates that. /animate-photos runs the same step (4b).
  • Generate now: serve.py runs the Higgsfield CLI after showing the cost. A Kling draft has been proven; Seedance by either path hasn't.

Round trip with CAS

  • In CAS, Ad set › Video › Add video offers "existing from CASV" or "Make a new one in CASV". The second opens …/Provident Video Studio.html#new=<ad set>; CASV keeps the previous project as "Reopen the last video".
  • Send to CAS records both sizes and a poster into _outbox/: <id>_9x16.mp4, <id>_1x1.mp4, <id>.jpg, <id>.json and <id>.casv. CAS polls the outbox every 3 seconds and uploads to <Main>/Video/ on Drive.
  • Timeline comments from CAS reach CASV through /api/outbox/notes (polled every 15 seconds) and show as ruler pins.
  • Open in Video Studio sends the .casv back through /api/outbox/back into _inbox/.
  • The ad set's QR code goes with Make a new one in CASV: CAS parks it as a JPEG on /api/inbox/photo and opens #new=<ad set>&qr=<id>; CASV puts it on the new video's QR code (P.brand.qr).
  • The ad set records the video as rs.video (op rsvideo). Who may add, replace or remove it depends on the signed-in role.
Exports record in real time (captureStream plus a WebAudio mix into MediaRecorder), so the tab must stay in front while it records.

Authentication and roles

There's one identity: the person's Google Workspace account at providentestate.com. Google gives the browser a Drive token; PDS's own server learns who the person is by asking Drive with that token, then looks up their role in its access list.

Google sign-in (providentDrive in studio-base.js)

  • OAuth client: an "Internal" consent screen, so only providentestate.com accounts can sign in. The client id is public by design; the secret is GOOGLE_CLIENT_SECRET in Vercel.
  • One scope, full auth/drive. Identity comes from /drive/v3/about, so no profile scope is requested.
  • The access token (about an hour) is kept in localStorage provident-drive-tok, shared by every tab and both studios.
  • The refresh cookie pgr is HttpOnly, Secure, SameSite=Strict and scoped to /api/gauth. It lasts 180 days, sliding, and is sealed with keys derived from the client secret, so rotating the secret signs everyone out.
  • invalid_grant clears the cookie. Sign-out revokes the token at Google.

The access gate (access.js + the acc* ops)

  • The gate is on only when ACCESS_ADMIN is set. The domain is ACCESS_DOMAIN (default providentestate.com); other domains get a 403.
  • An unknown company account becomes pending until the admin lets it in.
  • It applies to CAS and OPS. On Home it runs only for the admin panel. Review links (#share=) bypass it.
  • With no answer from the server, the hosted site fails closed. A file opened from disk opens normally.

The Grok bridge in detail

  • The token is the gate. The Google gate can't apply to a headless page, so remote.py requires Authorization: Bearer, or the token in the path (/t/<token>/mcp) for grok.com's URL-only connector form.

Section 15

Security posture and known risks

PDS protects data with Google Workspace and Drive sharing. The in-app role gate decides what people see, not what they can reach. Engineers adding features should keep that split in mind.

Controls in place

  • Internal OAuth consent screen: providentestate.com accounts only. The server re-checks the domain.
  • The server learns identity from Google, never from what the page claims.
  • Refresh tokens are kept out of JavaScript in an HttpOnly, Secure, SameSite=Strict cookie scoped to one path. /api/gauth needs a custom header and sends no CORS.
  • Admin and hub operations need their own keys, compared in constant time.
  • The public repo holds no secrets. They live in Vercel, a git-ignored .env, per-browser storage or per-Mac files (mode 0600).
  • The remote MCP needs a per-person token, logs every call, and keeps remote callers inside one folder.
  • Cost-bearing generation (Higgsfield, music) always shows a quote and waits for a yes.

Known risks, in order of priority

  • Full Drive scope, with the access token in localStorage. Any script injection on the site could act on the person's whole Drive. A narrower scope (drive.file) or keeping the token in memory would reduce this.
  • "View ad sets" is a view, not a lock. The read-only ad set page is enforced in the browser (no controls, handlers and dsApi refuse). A view-only person still holds a full Drive token, so what they can really change or download is decided by how the campaigns folder is shared with them. Give such accounts Viewer on the shared drive.
  • The role gate is client-side. Review links bypass it, linkGate runs after the ad set is already loaded, and Drive-link roles aren't enforced on any server.
  • Plain share links are bearer URLs on a CORS * API. Anyone holding a link can edit.
  • Loopback helpers send CORS *. Any web page could call /cutout, or /edit and /open, which launch Photoshop, or Generative fill's /expand, which spends the designer's Adobe generative credits or Higgsfield credits.
  • A token in the remote MCP path can end up in tunnel logs. Signed /f/ links open without a token for 14 days.
  • The refresh cookie is sealed with a home-made cipher (SHA-256 keystream + HMAC) rather than a vetted AEAD.
  • Identity is cached for 5 minutes, so a revoked person keeps access that long.
  • hubtasks accepts any Google token while ACCESS_ADMIN is unset. health and accstatus are public.
  • The Engine shows public repository data (commits, deployments) and connection health to the admin and AI Engineers; its feed (op=engine) is gated on the server, reports keys by name only, and the page escapes every value. The page shell itself is hidden on the client only.
  • Employee email addresses are hard-coded in api/share.py (access seed, Roam tags) and in tools/share-dev/serve.py, in a public repo.

Engineering rules, traps and removed features

Standing rules

  • A kit change fans out: edit ui-design-system/ first, then mirror into both studios' stylesheets and their JS style objects (inline styles win), then verify in the browser.
  • Prove the artwork didn't move: run an op-signature census against the pre-change file (both warm), or show a diff with zero artwork-path lines.
  • Check the winning value, not the rule: measure computed styles in the browser. The contrast bar is WCAG AA.
  • Brand on canvas: Google Sans Flex only (400 headers, 300 everything else, 500 tracked caps). No gold except the recorded exemptions. No orange on dark grounds. The wordmark goes left or centre, never right.
  • Update CAS-OPS-GUIDE.md and GROK-BOT-INSTRUCTIONS.md whenever something a user sees changes.
  • CAS ad-engine and video work stays off main until it's tested. Never push video-studio.

Recurring traps

  • No interpolated src=, d= or points=; use data-src. The browser fetches before DC interpolates.
  • data-x="{{ bool }}" renders "false", which [data-x] still matches.
  • A later duplicate key in an object literal silently wins; scan renderVals after edits.
  • Shrink the preview with a transform (StudioBase.scaleBox), never zoom.
  • Read photos only through StudioBase.sidecar() / img(). Use pointer events for drag, never native drag and drop.
  • In runtime.js, never declare a second var with an existing name. Bust the cache after editing studio-base.js or a .dc.html.
  • page.js in the MCP server calls engine internals by name. Rename one, and rename it there too.
  • The renderers read the face from window.providentFont. A canvas that draws a design other than the open one (another project, a review link) must run under that design's face, or Arabic copy lands in the fallback.
